> 草案，待使用者確認後再併入 SPEC.md（SPEC.md 由使用者編修，本檔不直接改 SPEC）。
> 2026-10-13 使用者提議並同意建議：拿掉「轉換為 Snapmaker U1」，匯出時自動存成 U1；
> 顏色維持量化到捲色（不加「保留原色」選項）；公仔設定與原檔線材設定衝突時以公仔設定為準。

### 3.16 匯出即轉為 Snapmaker U1（M35）

**背景**：目前有兩個產生 U1 檔的入口，功能互有缺漏：

| 項目 | 轉換為 U1（3.9） | 匯出 3MF（3.5b／3.5c／3.15） |
|---|---|---|
| 機型／process／線材設定名稱 | U1，依噴嘴設定 | U1，依噴嘴設定 |
| 盤面座標 | 換算到 U1 盤面（含多盤） | **不換算**：非 U1 檔的物件留在原機型座標，可能落在 U1 盤面外 |
| 相容性修正 | Exclude Object 開、Brim 關、可變層高時 Tree→Hybrid | 無 |
| 原檔 process 改動（`different_settings_to_system` 內、白名單） | 保留 | 剝除 |
| 原檔線材設定（溫度、流速、冷卻…白名單） | 保留 | 剝除 |
| 顏色 | 原檔顏色不動 | 量化到捲色、必要時寫 Mix |
| 輸出 | 另存 `-U1` 並匯入檔案櫃 | 存到使用者選的位置 |

使用者只需要一個「匯出成可直接在 U1 列印的檔案」的動作，因此合併為匯出。

- **移除**：詳情面板的「轉換為 Snapmaker U1」按鈕、轉換報告、「已轉換過，仍要再轉？」詢問（3.1b 的轉 U1 前提醒）。
  - 「已轉換過」詢問不需要替代品（使用者 2026-10-13：「如果再轉結果一樣，就不用詢問了」）：匯出存到使用者選的位置、不進檔案櫃，
    不會產生 `-U1-2`；存到同名檔時由 macOS 存檔視窗詢問是否取代（系統行為），App 不另外詢問。
  - 保留：「非 U1」徽章與側欄篩選（資訊用）；警示文字改為「這是 `<機型>` 的專案；匯出 3MF 時會自動轉為 Snapmaker U1」。
  - 資料：`source_printer`／`source_process` 照舊；`converted_from` 欄位保留（舊轉換檔的記錄），不再寫入新值。
  - 已在櫃中的 `-U1` 轉換檔不受影響。
- **匯出流程**（同一個「匯出 3MF…」按鈕，依序）：
  1. **盤面**：來源是非 U1 專案且有 `printable_area` → 以 3.9 的規則把各盤物件換算到 U1 盤面座標
     （保留排列、旋轉、縮放、Z 與盤間距；無法安全換算的盤整盤不動，匯出訊息列出原因）。
     來源已是 U1、或沒有專案設定（例如 Meshy 匯出）→ 座標不動（與現行匯出相同）。
  2. **相容性修正**：Exclude Object 開、Brim 關（選公仔時改用公仔的 10 mm 裙邊）。
     可變層高、層高範圍等來源切片檔照現行匯出剝除，因此不需要 Tree→Hybrid 修正。
  3. **原檔 process 改動**：沿用 3.9 白名單（`PROCESS_CARRY`）且列在來源 `different_settings_to_system` 的鍵，照樣帶入。
  4. **原檔線材設定**：沿用 3.9 白名單（`FILAMENT_CARRY`）。匯出後的耗材是使用者的捲槽，與原檔線材不是一對一：
     **每個實體捲槽採用「量化後映射到該槽面積最多的那條原檔線材」的設定**；沒有任何原檔線材映射到的槽用 U1 預設。
     混色虛擬擠出頭（Mix）不帶線材設定（Orca 依成分捲計算）。
  5. **顏色**：照現行量化到捲色、必要時寫 Mix（3.5b／3.5c），不加「保留原色」選項。
  6. **列印設定預設**（3.15）：原檔設定／公仔／公仔＋熨燙。與第 3、4 步衝突的鍵**以列印設定預設為準**，其餘原檔設定保留。
  - 所有寫入 `project_settings.config` 的覆寫都列入 `different_settings_to_system`（3.15 寫入規則）。
- **已是 U1 的檔案**：第 1 步不換算座標；第 2 步的修正照樣寫入；第 3、4 步依「待確認 3」
  （建議一律套用，因此與 M34 匯出的差別只在帶入的原檔設定，其餘相同）。
- **原檔不動**，匯出一律產新檔；全部本機處理，不連網。需要本機 Snapmaker Orca 的設定檔（同 3.9）；
  找不到時：U1 來源照現行匯出（只寫 U1 0.4 預設名稱），非 U1 來源顯示錯誤、不產生檔案。

**驗收**
- 使用者櫃中的真實非 U1 檔（3.9 的三個驗收檔：`Molly茉莉-太空人-13cm.3mf` H2S、`拉屎茉莉.3mf` P1S、`警徽多色.3mf` P1S）
  以「原檔設定」與「公仔」各匯出一次，在 Snapmaker Orca GUI 開啟：無相容性警告、物件在 U1 盤面內、多盤結構完整、可切片；
  原檔的溫度等線材設定出現在對應捲槽。
- 已是 U1 的檔案（如 `Wine-U1.3mf`、smoke 的 offpalette）：模型與盤面和 M34 匯出相同；`project_settings.config` 與 M34 逐項比對，
  差異只能是第 2～4 步寫入的鍵。
- 詳情面板不再有「轉換為 Snapmaker U1」；「非 U1」徽章、篩選與新警示文字正確（三種語言）。
- 原檔逐位元組不變；既有測試全數通過（原 3.9 轉換的單元測試改為測匯出流程中的對應步驟）。

**已決定（2026-10-13，使用者：照建議）**
1. 第 4 步「每槽採用映射面積最多的原檔線材設定」是否 OK？替代：全部捲槽都用第一條原檔線材的設定，或完全不帶線材設定。
2. 第 3 步帶入原檔 process 改動：會讓「原檔設定」匯出不再是純 U1 預設（例如原檔改了牆數就沿用）。是否 OK？
3. 已是 U1 的檔案也套用第 3、4 步（會帶入原檔設定，與 M34 匯出不同），還是 U1 來源維持 M34 行為不帶？建議：**一律套用**，行為一致。

**併入 SPEC 時**：3.9 改為「M35 起併入匯出，見 3.16」；3.1b 的「轉 U1 前提醒」標為移除。
