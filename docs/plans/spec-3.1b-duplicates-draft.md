### 3.1b 重複檔案偵測（M33）

**問題（2026-10-10 以使用者檔案櫃實測）**：匯入只比對檔名，內容完全相同的檔案再匯入一次會變成 `-2` 並多一筆記錄。
目前櫃中 156 筆記錄裡，有 2 組「大小與三角面數完全相同、放在不同資料夾」的檔案
（`Fast NO FUZZY-U1.3mf`／`2026/Fast NO FUZZY-U1.3mf`、`Filament+Swatch+Sample+Card-U1.3mf`／`色卡/Filament+Swatch+Sample+Card-U1.3mf`），
以及同一檔案轉兩次 U1 產生的 `警徽多色-U1-2.3mf`（是否逐位元組相同尚未驗證）。

- **重複的定義（只認內容）**：檔案內容的 SHA-256 指紋（`content_hash`）相同，才算「重複」。
  檔名、資料夾、匯入時間不列入判斷；同一模型被切片軟體重新存檔、轉 U1、改設定後內容不同，**不算重複**。
- **匯入時排除**（改 3.1 匯入流程第 1 步之前）：
  1. 搬檔前先讀來源檔算指紋（只讀不改）。
  2. 指紋與櫃中某筆記錄相同 → **不搬檔、不建記錄、來源檔原地不動**；
     匯入結果顯示「已在檔案櫃：`<rel_path>`，已略過」，可點擊跳到那筆記錄。
  3. 同一批裡有兩個相同檔案 → 只匯入第一個，其餘照第 2 點略過。
  4. 同名但內容不同 → 照現行規則加 `-2`、`-3` 匯入（不覆蓋，不變）。
  5. 重複對象在回收桶中 → 不匯入，提示「這個檔案在回收桶中」，並提供「從回收桶還原」。
- **既有記錄補指紋**：App 啟動後在背景逐檔計算，低優先、不阻塞操作；
  完成前，匯入只能比對已有指紋的記錄（需在 UI 註明「比對中，尚有 N 個檔案未建立指紋」）。
  檔案遺失或讀不到時略過，下次啟動再試。
- **「重複」篩選（側欄）**：列出指紋相同的分組（每組顯示各檔路徑、大小、匯入日期、來源與標籤），
  使用者自行決定刪哪個；刪除一律進 `.trash/`，**不自動刪除、不合併記錄**。
- **轉 U1 前提醒**：轉換前若櫃中已有由同一來源轉出的 U1 檔，先提示「已有 `<name>-U1`，仍要再轉一次？」，
  避免產生 `-U1-2`。需記錄轉換來源（新欄位 `converted_from`），舊的 `-U1` 檔沒有此資訊則不提示。
- **資料模型**：`models` 新增
  - `content_hash TEXT`（SHA-256 hex，可為 NULL＝尚未計算；建索引）
  - `converted_from INTEGER`（U1 轉換檔的來源記錄 id，可為 NULL）
  舊資料庫開啟時自動加欄位（沿用 `addColumn` 遷移方式），不動既有資料。
- **不做的**：不偵測「同模型、不同存檔」的近似重複；不自動刪除或合併；不比對回收桶以外的硬碟其他位置。
- **離線**：全部本機計算，不連網。

**驗收**
- 同一檔案匯入兩次：第二次不新增記錄、來源檔仍在原處且未被修改，提示含既有記錄路徑。
- 同名不同內容：照舊加 `-2` 匯入。
- 同一批拖入兩個相同檔案：只匯入一個。
- 重複對象在回收桶：不匯入，可從提示還原。
- 補指紋：以使用者檔案櫃實測，完成後「重複」篩選列出的分組經逐位元組比對確認相同；
  `兔子警官拆件单色.3mf`（186 MB）計算指紋的時間列入報告。
- 已有 `-U1` 轉換檔時再按「轉換為 Snapmaker U1」會先提示。
- 既有測試全數通過；舊資料庫開啟後欄位自動補上、資料不變。

**已決定（2026-10-10，使用者：依照建議）**
1. **iCloud 未下載到本機的檔案不補指紋**：以檔案旗標 `SF_DATALESS`（`0x40000000`，`sys/stat.h`；
   `stat -f %f` 只讀中繼資料、不觸發下載）判斷，未下載的略過，等使用者開啟或匯入時再算。
2. **不提供「仍要匯入」**：偵測到重複一律略過；需要時使用者自行改名或改內容再匯入。
3. **「疑似重複」本里程碑不做**。
4. **「重複」篩選不包含回收桶內的檔案**（匯入時仍會比對回收桶，見上方第 5 點）。
